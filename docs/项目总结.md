## 2. 需求分析（提炼）

### 2.1 背景与目标

- **痛点**：全网视频下载工具普遍要装 App / 看广告 / 限次数限清晰度；用户只想"粘贴链接，拿到文件"。
- **产品目标**：免费、免登录、不限次数的视频下载 + 字幕文本提取 Web 工具，手机电脑全端可用。
- **设计原则**（已确认的决策）：
  1. **零修改开源引擎**——yt-dlp 只以子进程封装，不 fork 不打补丁，可随上游升级；
  2. **零构建前端**——Vue3 本地 vendor，无 node 工具链，克隆即跑；
  3. **隐私最小化**——文件 2 小时自动清理，不存用户数据，任务仅存内存。

### 2.2 用户故事 → 功能映射

| 用户故事 | 对应功能 | 验收口径 |
|---|---|---|
| 我复制一个 B 站/抖音链接，想先看看是什么视频 | `POST /api/parse` | 秒级返回标题/封面/时长/清晰度 |
| 我想保存视频到本地 | `POST /api/download` + 进度轮询 + 文件下载 | 合并后的 MP4 可播放，进度真实 |
| 我只想要音频 | quality=mp3 | ffmpeg 转码 MP3（320k） |
| 我想把视频内容变成文字稿 | `POST /api/extract-text` | 字幕去时间轴/标签 → 纯文本 |
| 我不懂命令行，想双击就能用 | `start.bat` | 首次自动装依赖，重复启动直接开浏览器 |

### 2.3 非功能需求与达成

| 需求 | 达成方式 |
|---|---|
| 并发可控 | 下载信号量（3 并发，超出排队）；任务数上限 100 |
| 不卡死 | 解析 60s / 提取 90s / 下载行超时 120s 三级超时兜底 |
| 磁盘不涨 | 启动清理 + 每 30 分钟清理：文件 TTL 2h，字幕临时目录 10min |
| 错误可读 | `_friendly_error` 把 yt-dlp 原始报错翻译成用户语言（链接无效/需登录/已删除/超时…） |
| Windows 一键部署 | start.bat：venv 自举 + 依赖检测 + 端口占用检测 + ffmpeg 预检 |

## 3. 方案设计（含本次演进）

### 3.1 总体架构

```
浏览器（Vue3 SPA, 零构建）
   │  fetch /api/*
   ▼
FastAPI 单进程（main.py，同时静态托管 frontend/）
   │                    │
   ▼                    ▼
downloader.py        text_extractor.py
   │  asyncio.create_subprocess_exec("python -m yt_dlp", ...)
   ├── 常规平台：yt-dlp 解析/下载（B 站附加防风控 UA/Referer/伪 buvid3）
   ├── 抖音：douyin.py 免 Cookie 分享流（见 §3.3），下载时转直链仍由 yt-dlp 走统一进度/清理
   └── 任务表（内存 dict）+ downloads/ 文件 TTL 清理
ffmpeg：bv+ba 合并 MP4 / 音频转码 MP3
```

### 3.2 关键技术决策（ADR 摘要）

| 决策 | 理由 | 代价与边界 |
|---|---|---|
| 子进程封装 yt-dlp 而非 import | 进程隔离、进度可流式解析、上游升级零冲突 | 解析 JSON 而非对象；需要行级超时看门 |
| 任务仅存内存 | 免登录免数据库，重启即清，符合"临时文件"定位 | 重启丢任务（可接受：文件本来就 2h 过期） |
| `--print after_move:filepath` 拿最终路径 | yt-dlp 输出模板与合并/转码后的真实扩展名不可预知 | 需正则过滤绝对路径行 |
| 双分片进度折算 | bv+ba 两段下载进度会 0→100 回落两次，按"回落即新分片"折算总进度 | 直链/MP3 恒为 1 段 |
| 抖音独立通道（douyin.py） | yt-dlp 抖音通道需浏览器 JS 签名 Cookie，上游留有 TODO 无解 | 见 §3.3 |

### 3.3 抖音免 Cookie 通道（本次新增，重点沉淀）

**问题**：用户粘贴抖音链接（常为登录态个人主页弹窗链 `douyin.com/user/self?...&modal_id=N`）解析失败。

**根因有两层**（均经实验证实）：

1. **链接形态不识别**：yt-dlp 抖音提取器 `_VALID_URL` 只匹配 `douyin.com/video/{纯数字}`；`user/self?modal_id=` 永远 `Unsupported URL`。
2. **签名 Cookie 墙**：即便规范化为 `/video/{id}`，提取器调用的 web API `aweme/v1/web/aweme/detail/` 需要浏览器 JS 生成的指纹 Cookie（`s_v_web_id` 等）。实测匿名 `ttwid`、合成假 `s_v_web_id` 均被拒——yt-dlp 上游源码对此留有 TODO，属平台风控与解析器的军备竞赛，短期无解。

**方案：移动端分享页匿名通道**（`backend/douyin.py`，纯标准库，无新依赖）：

```
① HEAD https://www.douyin.com/（无 Cookie）
      → 服务端匿名下发 ttwid（HttpOnly、非登录态，内存缓存 20 分钟，失败自动换新重试）
② GET https://www.iesdouyin.com/share/video/{id}（移动端 UA + ttwid）
      → 页面 SSR 注入完整视频数据 window._ROUTER_DATA
      （item_list[0]：desc/author/cover/duration/play_addr…）
③ play_addr 的 url_list[0] 为 /aweme/v1/playwm/（带水印）入口
      → 路径替换 /playwm/ → /play/ 即无水印入口（码率反而更高：612 vs 303 kbps）
④ 两个入口均 302 至 douyinvod CDN，无需登录态可直接下载
```

**接入方式**：`main.py` 入口统一做链接规范化（`modal_id`/`video/`/短链 → `douyin.com/video/{id}`）；
`downloader.parse` 对抖音走 `douyin.parse_info`（返回结构与 yt-dlp 路径完全对齐）；
下载任务标记 `direct`，**下载时现取新鲜直链**（入口含时效签名），交给 yt-dlp 以直链模式下载
（无 `-f` 格式选择、`task_id.%(ext)s` 命名避免直链无视频 ID 撞名、移动端 UA），从而完全复用
既有的进度解析、任务视图、文件清理与 MP3 转码管线。

**边界（如实告知）**：分享流为单一 720P（无多清晰度档位）；抖音无字幕接口，文本提取明确报错待二期 Whisper 转写。

### 3.4 一键启动（start.bat）

无 Cookie 之外的可用性补强：双击即用——venv 不存在则自举并装依赖 → ffmpeg 预检（缺失仅警告）→ 端口已占用则直接开浏览器（防重复启动）→ 启动服务并延迟 3 秒自动打开 `http://127.0.0.1:8000`。CRLF + `chcp 65001` 保证中文在 cmd 下正常显示。

## 4. 踩坑复盘

| 坑 | 现象 | 解法 |
|---|---|---|
| 抖音 `user/self?modal_id` 链接 | `Unsupported URL`，用户以为"平台不支持" | 入口统一规范化为 `/video/{modal_id}` |
| 抖音 web API 签名墙 | `Fresh cookies (not necessarily logged in) are needed` | 放弃 web API，改走分享页 + 匿名 ttwid（§3.3） |
| 分享页 SSR 空 | 不带 ttwid 时 `_ROUTER_DATA` 无 `videoInfoRes` | 携带匿名 ttwid 即注入；实现层 ttwid 失效自动换新重试一次 |
| 水印 | 分享流 `playwm` 入口带平台水印 | 入口路径 `playwm→play` 替换即无水印（抽帧视觉验证） |
| 直链下载撞名 | 直链 URL 不含视频 ID，`%(id)s` 模板多任务同名 | 直链任务改用 `task_id.%(ext)s` 输出模板 |
| bv+ba 进度回落 | 总进度 0→100 跳两次，前端体验差 | "进度回落即新分片"折算 2 段加权 |
| Git Bash 提交中文 JSON | curl body 编码破坏 JSON 解析 | 测试用无中文 body / `--data-binary @file` |
