## 3. API 契约

| 方法 路径 | 鉴权 | 说明 |
|---|---|---|
| POST /api/auth/register `{email,password}` | - | 注册即登录（Set-Cookie `sd_session`） |
| POST /api/auth/login `{email,password}` | - | 登录；限流 10 次/分/IP |
| POST /api/auth/logout | Cookie | 清会话 |
| GET /api/auth/me | Cookie | `{logged_in, account{is_vip,vip_expires_at}}`（匿名 200） |
| GET /api/quota | 可选 | `{mode: anonymous|account|vip, limit, used, remaining}` |
| GET /api/vip/plans | - | 服务端定价（金额只出自 config.PLANS） |
| POST /api/vip/checkout `{plan_id}` | 需登录 | `{order_id, checkout_url}`；复用 pending 订单防重复付款 |
| GET /api/vip/order/{id} | 订单属主 | 轮询；pending 时主动向 Stripe 核实并幂等履约（webhook 兜底） |
| POST /api/vip/activate `{code}` | 需登录 | 兑换码（订单码全局单次；演示码每账号一次） |
| POST /api/webhooks/stripe | 签名 | 验签→事件去重→幂等履约；失败 400/500 |

额度计费点：`/api/summarize`、`/api/qa`（每轮）、`/api/analyze(include_summary=true)`、
`/api/analysis/{id}/summarize` 与带总结 retry——发起即预扣（防重试刷量），超限 402，
前端据 402 唤起登录（匿名）或会员弹窗（已登录）。

## 4. 安全与幂等（均对应自动化测试）

1. **验签**：原始 body + `Stripe-Signature` + whsec → `construct_event`；错签/超 300s 旧时间戳 → 400（`test_webhook_bad_signature_rejected` 等 3 例）
2. **事件去重**：`webhook_events(event_id PK)`，重复投递直接 200 跳过（`test_duplicate_webhook_delivery_extends_only_once`：会员仅 +30 天）
3. **状态机**：`UPDATE orders SET status='paid' WHERE id=? AND status='pending'` rowcount 守卫；续期/发码仅在首次成功后执行（`test_concurrent_fulfillment_of_two_paid_sessions_for_same_order`：两个不同事件 ID 同订单也只 +30 天）
4. **防重复付款**：`(account_id, plan_id) WHERE status='pending'` 部分唯一索引 + 复用未过期会话；会话过期则同订单换发（`test_checkout_reuses_pending_order_no_duplicate_session`）
5. **服务端定价**：客户端只传 plan_id（`test_checkout_creates_pending_order_with_server_side_price`）
6. **webhook 丢失兜底**：订单轮询主动 retrieve Stripe 核实 `payment_status=='paid'` 后走同一 `_fulfill_order`（`test_order_polling_fulfills_when_webhook_lost`）
7. **履约失败可重试**：异常时 `forget_event` 回滚去重记录并返 500，Stripe 自动重投
8. **账号安全**：scrypt(n=2^14) 加盐、库存 SHA-256 会话令牌、HttpOnly+SameSite=Lax、登录恒时差（不存在账号也做同样 scrypt）

## 6. 已知限制（二期方向）

- 未做邮箱验证/找回密码（需 SMTP）；密码找回暂只能清库重建
- 匿名额度按 IP 记，代理可绕过（登录额度按账号不受影响）
- 退款（`charge.refunded`）未自动回收会员，需管理员手工处理
- 订阅制、发票、多套餐并行、管理后台（订单/用户查询）留二期
